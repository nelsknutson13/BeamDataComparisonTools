Overview

BeamDataAvgTool builds a fleet average beam profile from multiple machines, quantifies how well each machine tracks that average, and flags clinical and statistical outliers.

The tool loads a multi-sheet Excel file where each sheet is one machine's measurement. It resamples all profiles to a common position grid, computes a mean and standard deviation at each point, and plots prediction bands and confidence intervals around the average. A text report summarises per-machine deviation statistics and applies a fleet-relative outlier test.

Typical use: annual or quarterly linac QA — load measurements from your fleet, generate the average as a reference, then compare any new measurement against that reference.

Workflow

  1. Load a file
    Use Browse to select an Excel workbook. Each sheet should contain one machine's beam data (profiles or PDDs).
  2. Select sheets, field sizes, and depths
    Check or uncheck sheets in the Sheet Selection list. Use the Field Size and Depth lists to filter which combinations are processed.
  3. Set tolerances and plot parameters
    Adjust Dose Tol, Pos Tol, SD mult, and CI% in the control row before plotting (see Controls below).
  4. Plot Data
    Click Plot Data to view the raw profiles overlaid on the same axes. No averaging is done yet.
  5. Make Avg
    Click Make Avg to compute the fleet mean, SD, and confidence bands. The plot updates with shaded bands around the mean.
  6. Save Avg
    Optionally save the averaged profile to a new Excel file for use as a reference baseline.
  7. Print / Save Report
    Click Print Report to display the deviation table and outlier flags in the console, or Save Report to write it to a text file.

Data & tolerance controls

ControlWhat it does
Min datasets Minimum number of machine sheets required before a combination (field size + axis + depth) is included in the average. Combinations with fewer sheets are skipped.
Dose Tol Clinical dose tolerance in %. A point is "within tolerance" when its deviation from the fleet mean is less than this value. Drives the Tol% column in the report.
Pos Tol Clinical position tolerance in mm. Used in the DTA (distance-to-agreement) search for the Max dev† column: a point's DTA must exceed this threshold before it is considered a position-driven outlier rather than a dose outlier.
SD mult (k) Multiplier on the standard deviation for the prediction band. k = 2.326 gives 98% coverage under a normal distribution; k = 2.0 gives ~95%. Controls both the shaded band on the plot and the Pred% column in the report.
CI% Confidence level for the CI-on-mean band (t-distribution). Shared with the prediction band percentage. The CI on mean shrinks as more machines are added; the prediction band does not.

Preprocessing

ControlWhat it does
PDD normalisation Choose the depth or percentage at which each PDD is normalised before averaging. This ensures all machines contribute equally regardless of absolute output differences.
Manual Profile Shifts… Opens a dialog to apply a manual lateral shift (in cm) to individual machine profiles. Use this to correct for known couch or detector positioning offsets before computing the average.

Plot settings

Profile / PDD inset Add a zoom inset to the profile or PDD plot. Set x-range, y-range, and corner position for the inset axes.

Plot window

After Make Avg, the plot shows three overlapping bands around the fleet mean:

Tolerance band — ±Dose Tol% around the mean. Points outside this band fail the clinical criterion.
Prediction band — ±k·SD around the mean. Represents where a randomly drawn machine from the fleet is expected to fall. Does not shrink as n increases.
CI on mean — ±t·SE around the mean (SE = SD/√n). Represents uncertainty in the mean itself. Shrinks as more machines are added. Uses the t-distribution to account for small n.
Prediction vs CI on mean: if a machine's profile falls outside the prediction band, it's unusual relative to the fleet. If the CI on mean is wide, the fleet average itself is not well-determined — you need more machines.

The dashed black lines mark the outer edges of whichever bands are enabled. Individual machine profiles are plotted as scatter points; the fleet mean is a solid line.

Report columns

Each row in the report corresponds to one machine (sheet). Deviations are computed point-by-point against the fleet mean at the resampled grid positions.

ColumnDefinition
n Number of valid (non-NaN) comparison points for this machine in this combination.
Mean dev Signed mean of all point deviations: mean(machine − avg). A non-zero value indicates a systematic bias — the machine runs high or low relative to the fleet on average.
RMS dev Root-mean-square deviation: √mean((machine − avg)²). Sensitive to both systematic offset and random spread. The primary metric for statistical outlier detection.
P95 dev 95th percentile of |machine − avg|. A robust near-maximum: 95% of points fall within this deviation. Less affected by a single extreme point than Max dev.
Max dev Maximum absolute deviation across all points. Corresponds to the worst single-point disagreement regardless of position.
Max dev† Maximum deviation restricted to points where DTA > Pos Tol. DTA is computed by searching along the average profile for the nearest point with the same dose value. If all points are within Pos Tol, the value is reported at the point of maximum DTA instead. This isolates dose errors from position errors in the high-gradient penumbra region.
Tol% Percentage of points within the clinical dose tolerance (Dose Tol). A value of 100% means the machine meets the dose criterion at every comparison point.
Pred% Percentage of points within the prediction band (±k·SD). Values below 100% indicate points that fall outside the range expected for a typical fleet member.

Statistical outlier flags

The FLAGS section at the bottom of the report uses the modified Z-score (Iglewicz–Hoaglin method) to identify machines that are statistically unusual relative to the rest of the fleet.

Why not just a clinical threshold?

A clinical threshold (e.g. "fail if >1% deviation") answers a fixed question: does this machine meet the specification? The statistical test asks a different question: is this machine behaving differently from its peers, even if it technically passes? A machine can pass the clinical criterion and still be an outlier if the rest of the fleet is performing better.

The modified Z-score (M)

For a set of values across the fleet, the M score for one machine is:

M = 0.6745 × (x − median) / MAD

where MAD is the median absolute deviation from the median. The 0.6745 factor scales M so that it matches a standard Z-score for normally distributed data.

Key advantage: the MAD uses the median, not the mean, so an outlier machine does not inflate the reference statistics and partially hide itself. Each machine is compared to the fleet without its own value distorting the yardstick.

Interpreting M scores

|M|Interpretation
0 – 1Well within normal fleet variation
1 – 2Slightly elevated, not remarkable
2 – 3Elevated; worth watching
3 – 3.5Near threshold; monitor closely
3.5+Flagged — statistically unusual relative to fleet
7+Strongly unusual — fleet distribution would need to shift dramatically for this machine to look typical

What gets tested

The FLAGS section runs the modified Z-score independently on three metrics from the summary table, using the per-machine values across all combinations:

  • Mean dev — detects systematic bias (machine consistently high or low)
  • RMS dev — detects excess random variation or combined bias + noise
  • P95 dev — detects machines with frequent large-magnitude excursions

A machine is flagged if it exceeds the threshold (|M| > 3.5) on any of the three. The report shows which metric triggered and the exact M value. If no machine exceeds the threshold, the section prints "No statistical outliers detected."

Minimum fleet size: the FLAGS section requires at least 3 machines. With fewer than 3 machines the section is omitted — there is no meaningful fleet distribution to compare against. The test becomes increasingly reliable as the fleet grows.

Two-failure-mode interpretation
